本章重点

面对一个页面，先观察它由哪些区域组成，再判断是“一维排列”还是“二维区域”，最后考虑尺寸是否需要随屏幕变化。

本章学习目标

先理解“空间怎么分”，再写 CSS

页面布局解决的不是“把元素放到某个坐标”，而是规定页面中的元素如何形成结构、如何分配剩余空间，以及内容增多或窗口缩小时如何保持可读性。本章通过盒模型、Flexbox、Grid 和媒体查询建立一套完整的布局思维。

学习时建议始终从父元素入手：先确定容器的布局方式，再观察子元素如何参与空间分配。这样遇到“挤开了、撑大了、换行了、手机端乱了”等问题时，才能快速定位到对应的 CSS 规则。

6.1

盒模型：元素到底有多宽？

CSS 中一个元素的尺寸由 content、padding、border 和 margin 共同影响。

基础概念

一个盒子并不只有“内容”这一层

一个网页元素可以把空间理解为四层：content 是真正承载文字或图片的内容区；padding 是内容与边框之间的内部留白；border 是元素边界；margin 则负责与其他元素保持外部距离。理解这四层，是排查“尺寸不对、间距不对”的第一步。

在默认的 content-box 模型中，width 只约束 content，因此最终占位宽度还要继续加上左右 padding 和左右 border。切换到 border-box 后，声明的 width 会把 padding 与 border 一起计算进去。

实际宽度 = content + padding + border

在实际项目中，通常在入口处统一设置 box-sizing: border-box。这样按钮、卡片、输入框等组件在调整 padding 时，不容易意外突破原来的宽度约束，也更利于建立稳定的栅格和列宽。

/* 推荐：项目入口统一设置 */
*, *::before, *::after {
  box-sizing: border-box;
}

.card {
  width: 320px;
  padding: 24px;
  border: 4px solid #4f46e5;
}

/* 如需切换模型，只改变这一行 */
.card { box-sizing: content-box; }
⭐ 关键点 统一设置 border-box 可以让组件的声明尺寸更接近最终占位尺寸，特别适合卡片、表单控件和栅格列。
⚠️ 常见坑 只看 width 而忽略 padding、border，是初学者最容易遇到的尺寸误判；排查时要把四层盒模型一起考虑。

6.2

Flexbox：把一排元素排整齐

Flex 适合导航栏、按钮组、水平卡片、工具栏等“一维布局”。

一维布局

Flexbox 的核心是“沿一个方向分配空间”

主轴 →
↕ 交叉轴

Flexbox 适合解决一维布局：例如导航栏中的多个按钮、工具栏中的标题与操作区、横向排列的卡片等。容器先声明 display: flex，之后由主轴和交叉轴两个方向决定项目如何分布。默认主轴是水平方向。

justify-content “一排元素怎么分布？”
align-items “交叉方向怎么对齐？”
gap “元素之间留多少？”

如果你描述一个布局时会说“这一排元素”“左右两边”“垂直居中”“按钮紧挨着排列”，通常可以先尝试 Flex。对于需要同时控制行和列的复杂区域，再考虑 Grid。

justify-content 处理主轴上的空间分配，例如靠左、居中、两端对齐或平均分布；align-items 处理交叉轴上的对齐，例如顶部、居中、底部或拉伸。gap 则负责项目之间的统一间距，比给每个元素分别设置 margin 更容易维护。 

.nav {
  display: flex;
  align-items: center;
  justify-content: space-between;
  gap: 20px;
}

.cards {
  display: flex;
  gap: 16px;
}

.cards > * {
  flex: 1;
}
⭐ 关键点 先让容器成为 Flex，再根据页面目标分别设置主轴分布、交叉轴对齐和项目间距，避免一次修改多个属性却不知道谁起作用。
💡 经验 “横向排列 + 垂直居中”是最常见的 Flex 场景，例如导航栏、工具栏和按钮组。

6.3

CSS Grid：搭建二维页面骨架

Grid 同时处理行和列，非常适合数据看板、卡片矩阵和“侧栏 + 主区”结构。

二维布局

Grid 更适合“有行有列”的页面结构

Sidebar
Main
Footer

CSS Grid 把容器看作一个由行和列组成的二维网格。你可以先定义列轨道，再让不同模块占据一个或多个网格单元，因此非常适合数据看板、后台管理页、卡片矩阵以及侧栏 + 主内容这类结构。

columns 定义列的宽度和数量
rows 定义行的高度和数量
span 让项目跨越多列或多行

绝对定位可以快速得到某个视觉效果，但它不会自动参与正常的文档流和空间分配。内容长度、字体大小或屏幕宽度一旦变化，元素就容易重叠。能用 Flex 或 Grid 表达的结构，优先使用正常布局。

grid-template-columns: 220px 1fr 是很典型的页面骨架：第一列给侧栏一个相对稳定的宽度，第二列使用 1fr 接收剩余空间。fr 表示“可分配的剩余空间”，多个 1fr 会把可用空间按比例分配。 

.page {
  display: grid;
  grid-template-columns: 220px 1fr;
  gap: 24px;
}

.dashboard {
  display: grid;
  grid-template-columns: repeat(4, 1fr);
  gap: 16px;
}

.feature {
  grid-column: span 2;
}
⭐ 关键点 Flex 更擅长一维排列，Grid 更擅长二维区域；复杂页面通常不是二选一，而是让二者在不同层级各司其职。
⚠️ 常见坑 大量 absolute 会绕开正常布局流，内容变化后容易发生重叠；能用 Grid 或 Flex 表达的结构应优先用正常布局。

6.4

响应式布局：让页面适应屏幕

通过流式尺寸、弹性空间和媒体查询，让同一套页面适配桌面端与移动端。

响应式

响应式不是“缩小桌面网页”

响应式设计的目标是在不同屏幕尺寸下保持信息层级和操作逻辑，而不是简单地把所有元素按比例缩小。桌面端可以使用多列结构，移动端则可能需要减少列数、压缩间距、改变排列方向，甚至调整导航方式。

流式 % / fr / minmax()
弹性 Flex / Grid 自动分配空间
断点 @media 按屏幕宽度调整

不要机械地认为所有页面都必须在某个固定设备宽度切换。更合理的方法是观察内容什么时候开始拥挤、按钮什么时候放不下、卡片什么时候过窄，然后在那个宽度附近设置断点。

流式布局使用 %、vw、fr 等相对单位；弹性布局利用 Flex 和 Grid 自动分配空间；媒体查询则在达到某个宽度后主动改变规则。例如屏幕变窄时，把“侧栏 + 主区”从两列改成单列。 

.layout {
  display: grid;
  grid-template-columns: 220px minmax(0, 1fr);
}

@media (max-width: 768px) {
  .layout {
    grid-template-columns: 1fr;
  }

  .sidebar {
    position: static;
  }
}
⭐ 关键点 无论桌面优先还是移动优先，都应根据“内容什么时候开始拥挤”来选择断点，而不是机械套用某个设备尺寸。
💡 推荐 fr、minmax() 等弹性单位能让容器在可用空间变化时自动调整，减少固定 px 导致的溢出。

6.5

综合案例：从零搭建数据看板

外层用 Grid，工具栏用 Flex，卡片区用 Grid，再用媒体查询完成响应式适配。

综合实践

完整页面通常是多种布局技术叠加

Page Grid：页面大区
→
Toolbar Flex：按钮与标题
→
Cards Grid：多卡片排列

布局学习的最终目标不是背诵 justify-content、grid-template-columns 等属性，而是看到页面时能先画出结构，再选择最合适的布局方式。结构确定之后，CSS 就从“调位置”变成了“描述规则”。

可以先用 Grid 将页面分成主区域；顶部工具栏用 Flex 将标题、筛选器和操作按钮分开；指标卡片继续用 Grid 形成规则矩阵；图表区域根据内容设置跨列关系；最后通过媒体查询减少列数，让手机端仍然保持清晰的阅读顺序。

真实项目很少“全站只用 Flex”或者“全站只用 Grid”。更常见的方式是分层：最外层负责页面区域，区域内部再分别选择合适的布局工具。这样每个容器只解决一个清晰的问题，结构更容易理解。 

.page {
  display: grid;
  grid-template-rows: auto 1fr;
}

.toolbar {
  display: flex;
  align-items: center;
  justify-content: space-between;
}

.dashboard {
  display: grid;
  grid-template-columns: repeat(4, 1fr);
  gap: 16px;
}

@media (max-width: 768px) {
  .dashboard { grid-template-columns: 1fr 1fr; }
}
⭐ 核心思路 先把页面拆成 header、sidebar、main、cards 等区域，再让每个区域选择合适的布局工具，比直接给元素写坐标更稳定。

本章总结

遇到布局问题，先判断结构，再决定属性

① 是一维还是二维？ 先分清页面是一排元素、还是一个行列区域：前者通常从 Flex 开始，后者通常从 Grid 开始。
② 尺寸应该固定吗？ 能使用 fr、%、minmax() 等弹性单位时，不必把所有尺寸写死为 px；固定尺寸应只用于确实需要稳定宽度的区域。
③ 窗口变窄怎么办？ 最后检查窄屏：观察内容是否拥挤、按钮是否换行、卡片是否过窄，再通过媒体查询调整列数、间距或排列方向。
