本章重点

页面布局的目标不是记住某个属性，而是学会根据页面结构选择合适的布局方式。

本章学习目标

先理解“空间怎么分”，再写 CSS

一个网页通常由多个区域组成：导航、侧栏、内容区、卡片、按钮。布局技术负责决定这些区域如何排列、如何占据空间，以及当窗口变窄时如何自动调整。

6.1

盒模型：元素到底有多宽？

CSS 中一个元素的尺寸由 content、padding、border 和 margin 共同影响。

基础概念

为什么写了 width: 320px，结果却比 320px 更宽？

默认的 content-box 中，width 只计算内容区域。若再加上 24px 的左右内边距和 4px 的左右边框，元素的实际占用宽度会继续增加。

实际宽度 = content + padding + border

开发中最常用的解决方案是统一设置 box-sizing: border-box，让 width / height 把 padding 和 border 一起算进去。

margin
border
padding
content
content-boxwidth 只控制 content
border-boxwidth 包含 padding + border
/* 推荐：项目入口统一设置 */
*, *::before, *::after {
  box-sizing: border-box;
}

.card {
  width: 320px;
  padding: 24px;
  border: 4px solid #4f46e5;
}

/* 如需切换模型，只改变这一行 */
.card { box-sizing: content-box; }
⭐ 关键点border-box 能让“设定尺寸”和“看到的尺寸”更容易对应起来。
⚠️ 常见坑只看 width，不看 padding / border，是初学者最常见的尺寸误判。

6.2

Flexbox：把一排元素排整齐

Flex 适合导航栏、按钮组、水平卡片、工具栏等“一维布局”。

一维布局

先抓住两个方向：主轴 + 交叉轴

默认情况下，Flex 的主轴是水平的。justify-content 管主轴上的分布，align-items 管交叉轴上的对齐，gap 管项目之间的距离。

justify-content“一排元素怎么分布？”
align-items“交叉方向怎么对齐？”
gap“元素之间留多少？”
.nav {
  display: flex;
  align-items: center;
  justify-content: space-between;
  gap: 20px;
}

.cards {
  display: flex;
  gap: 16px;
}

.cards > * {
  flex: 1;
}
⭐ 关键点先写 display: flex，再根据需求决定主轴分布和交叉轴对齐。
💡 经验“横向排列 + 垂直居中”是 Flex 最典型的使用场景。

6.3

CSS Grid：搭建二维页面骨架

Grid 同时处理行和列，非常适合数据看板、卡片矩阵和“侧栏 + 主区”结构。

二维布局

Grid 更像是在“画页面的骨架”

Sidebar
Main
Footer

例如 grid-template-columns: 220px 1fr 可以把页面划成固定宽度的侧栏和自适应的主内容区；1fr 表示把剩余空间分给这一列。

columns定义列的宽度和数量
rows定义行的高度和数量
span让项目跨越多列或多行
.page {
  display: grid;
  grid-template-columns: 220px 1fr;
  gap: 24px;
}

.dashboard {
  display: grid;
  grid-template-columns: repeat(4, 1fr);
  gap: 16px;
}

.feature {
  grid-column: span 2;
}
⭐ 关键点Flex 强在“一维排列”，Grid 强在“二维区域”。实际页面经常两者组合。
⚠️ 常见坑不要为了“看起来整齐”给每个元素写大量绝对定位，内容变化后很容易失控。

6.4

响应式布局：让页面适应屏幕

通过流式尺寸、弹性空间和媒体查询，让同一套页面适配桌面端与移动端。

响应式

不要把“手机页面”理解成另一套网页

响应式设计的核心是：内容和结构尽量复用，在屏幕变窄时改变列数、间距、字号或区域排列。

流式% / fr / minmax()
弹性Flex / Grid 自动分配空间
断点@media 按屏幕宽度调整
.layout {
  display: grid;
  grid-template-columns: 220px minmax(0, 1fr);
}

@media (max-width: 768px) {
  .layout {
    grid-template-columns: 1fr;
  }

  .sidebar {
    position: static;
  }
}
⭐ 关键点桌面优先或移动优先都可以，关键是明确“什么时候需要改变布局”。
💡 推荐优先使用 fr、minmax() 等弹性单位，减少固定像素依赖。

6.5

综合案例：从零搭建数据看板

外层用 Grid，工具栏用 Flex，卡片区用 Grid，再用媒体查询完成响应式适配。

综合实践

一个完整页面通常不是“只用一种布局”

PageGrid：页面大区
→
ToolbarFlex：按钮与标题
→
CardsGrid：多卡片排列

真正写项目时，可以把布局问题分层处理：外层负责“区域怎么分”，内层负责“元素怎么排”。这样结构清晰，也更容易维护。

.page {
  display: grid;
  grid-template-rows: auto 1fr;
}

.toolbar {
  display: flex;
  align-items: center;
  justify-content: space-between;
}

.dashboard {
  display: grid;
  grid-template-columns: repeat(4, 1fr);
  gap: 16px;
}

@media (max-width: 768px) {
  .dashboard { grid-template-columns: 1fr 1fr; }
}
⭐ 核心思路先拆区域，再选择布局；不要一看到“位置”就想到 absolute。

本章总结

遇到布局问题，先问自己三个问题

① 是一维还是二维？一排元素优先考虑 Flex；行列区域优先考虑 Grid。
② 尺寸应该固定吗？能用 fr、%、minmax() 解决时，不必全部写死 px。
③ 窗口变窄怎么办？用媒体查询、换列数或调整间距完成响应式。
